1//! MPC-TLS session driver for platform API notarization using TLSNotary.
2//!
3//! This crate provides prover and verifier functionality for establishing
4//! TLS connections to any HTTPS API while generating cryptographic proofs
5//! that can be verified by a third party. It is the only crate in the libID
6//! workspace that touches `tlsn` types — everything byte-oriented (range
7//! math, wire protocol, proof types) lives in `libid-transcript`, which is
8//! published to crates.io. This crate is git-only until upstream tlsn is
9//! published (see Cargo.toml).
10//!
11//! # Cryptographic Guarantee: Why the Prover Cannot Fake Revealed Data
12//!
13//! TLSNotary uses a multi-party computation (MPC) protocol to split the TLS
14//! session keys between the prover and the verifier (notary). Neither party
15//! holds the full key material alone — the TLS MAC key and encryption key are
16//! secret-shared. During the TLS session, both parties jointly compute the
17//! HMAC and decryption operations via 2PC (two-party computation), so the
18//! actual plaintext is only assembled inside the MPC circuit.
19//!
20//! When the prover later reveals portions of the transcript, the verifier can
21//! confirm authenticity because:
22//!
23//! 1. **Commitment phase**: During the MPC-TLS session, the prover commits to
24//!    the full transcript (sent and received bytes) using hash-based
25//!    commitments. These commitments are bound to the ciphertext that both
26//!    parties observed on the wire.
27//!
28//! 2. **Selective disclosure**: After the session closes, the prover opens
29//!    specific byte ranges of the transcript by revealing the plaintext and
30//!    the corresponding commitment opening. The verifier checks that the
31//!    opened plaintext, when encrypted under the jointly-held session key,
32//!    produces the exact ciphertext that was recorded during the live TLS
33//!    session.
34//!
35//! 3. **Server identity binding**: The TLS handshake — including the server's
36//!    certificate chain, ephemeral key, and ServerHello random — is verified
37//!    by the notary against the WebPKI root store during the MPC-TLS session.
38//!    The server name (SNI) is therefore authenticated by the CA hierarchy,
39//!    not merely asserted by the prover.
40//!
41//! Because the session keys are never fully available to the prover alone, the
42//! prover cannot forge a valid ciphertext/plaintext pair. Any attempt to alter
43//! the revealed plaintext would fail the commitment verification: the modified
44//! plaintext would not match the ciphertext that was jointly observed and
45//! committed to during the live session. This makes the revealed data as
46//! trustworthy as the TLS session itself — the prover can choose *which* parts
47//! to reveal, but cannot fabricate *what* those parts contain.
48//!
49//! # Why the Notary Does Not Need a Domain Whitelist
50//!
51//! The TLS server name (SNI) is authenticated by the WebPKI certificate chain
52//! during the MPC-TLS handshake. The notary (verifier) validates the server's
53//! certificate against the WebPKI root store in real time, as part of the
54//! joint TLS computation. Because the handshake keys are secret-shared, the
55//! prover cannot substitute a different certificate or redirect the connection
56//! to a different server without breaking the MPC-TLS protocol. The domain
57//! extracted from SNI is therefore a cryptographic fact — not an assertion by
58//! the prover — and the notary can safely use it without maintaining any
59//! platform-specific domain list.

89/// Errors from MPC-TLS session driving.
90#[derive(Debug, thiserror::Error)]
91pub enum Error {
92    /// The MPC-TLS protocol failed.
93    #[error("MPC-TLS failed: {detail}")]
94    MpcTlsFailed {
95        /// Human-readable failure detail.
96        detail: String,
97    },
98    /// The TLS session used a version the proof pipeline does not support.
99    #[error("unsupported TLS version: {detail}")]
100    UnsupportedTlsVersion {
101        /// Human-readable failure detail.
102        detail: String,
103    },
104    /// Socket I/O failed.
105    #[error("io: {0}")]
106    Io(#[from] std::io::Error),
107    /// Transcript parsing failed.
108    #[error(transparent)]
109    Transcript(#[from] libid_transcript::Error),
110}

112/// Result alias for this crate.
113pub type Result<T> = std::result::Result<T, Error>;
